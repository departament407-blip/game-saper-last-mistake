# Послевзрывная проверка флагов

Реализован пункт 3.3 задания от 2026-11-05. База: `main` / `ab2854d3c266634dd288524ad57c0aeb6f63a7d8`, совпадение с GitHub проверено перед изменениями. Полный аудит игры и переработка баланса в этот этап не входят.

## Архитектура

- `src/ui/postBlastFlags.ts` создаёт замороженный снимок классификации и счётчиков. Модуль не вызывает методы ядра, не меняет `Cell`, XP, HP, результат операции или сохранения. Собственных таймеров и обработчиков кадров нет.
- `BoardView` запускает проверку только на `RUN_LOST`, после завершения операции и progression в `RunManager`. Предварительный `CELL_REVEALED` со статусом `lost` не запускает проверку флагов. До подрыва одинаковы SVG, CSS-классы и смысл ARIA у всех флагов.
- `src/ui/boardObjects.ts` содержит SVG обычного флага, его обугленного состояния, подтверждения, креста и моделей мин. Правильный флаг использует исходную форму, красный цвет и контрастное древко.
- `src/ui/postBlastFlags.css` отвечает за повреждение полотнища, пламя, дым, пепел, наклон древка и постоянный крест. Цвет дыма, огня и высота пламени зависят от существующего биома. Число SVG-элементов ограничено числом флагов; генератора частиц нет. Декоративные слои не перехватывают ввод.
- Один экземпляр `PostBlastFlags` передаётся в `BoardView` и `HudView`. Статистика дебрифинга использует тот же снимок, что и поле.

## Классификация и статистика

| Условие на момент детонации | Отображение |
| --- | --- |
| `flagged && hasMine` | Целый красный флаг с небольшой зелёной галочкой; без классов обгорания |
| `flagged && !hasMine` | Горящее полотнище → обугленный частичный остаток, наклонённое древко, красный крест |
| `!flagged && hasMine` | Металлическая модель неотмеченной мины |
| `explodedCellId` | Отдельный силуэт мины с раскалённой трещиной и кольцом эпицентра |

Неотмеченные мины включают взорвавшуюся мину. Удалённые ранее флаги не учитываются. Исторический штраф `wrongFlagPenaltyIds` не используется. Автофлаги Рома классифицируются по реальным данным наравне с ручными флагами. Счётчики и описания для экранного диктора переведены на ru/en/es.

## Последовательность

| Время | Состояние |
| --- | --- |
| 0–900 мс | Детонация и ударная волна; ошибочные флаги ещё целые |
| 900–2500 мс | Огонь охватывает полотнище, края темнеют и разрушаются; правильные флаги сохраняются |
| 2500–4000 мс | Древко наклоняется, отделяется пепел, появляется крест, огонь затухает |
| От 4000 мс | Дебрифинг поверх сохранённого разрушенного поля; крест и подтверждённые флаги остаются |

`BLAST_TIMING` задаёт границы фаз. При повторном рендере отрицательные CSS-задержки учитывают уже прошедшее время — флаги не начинают гореть заново. Общие вспышка и ударные волны завершаются к 900 мс. Поднятие доски над дымом и исключение родительского фильтра сохраняют цвет правильных флагов.

При `prefers-reduced-motion: reduce` сразу показывается статический результат с теми же отметками и статистикой; вспышка, огонь, дым, дрожание и пепел отключены. Дебрифинг по-прежнему появляется через четыре секунды.

## Жизненный цикл

`GAME_STARTED`, `GAME_RESET` и `clearOutcomeState()` очищают снимок, DOM результатов и временные CSS-параметры. Уход с операции отменяет ожидающие таймеры сцены/дебрифинга. Ревизия сцены не позволяет поздней загрузке разрушенного фона вернуть его после очистки.

Временный переход в профиль сохраняет разрушенную сцену. Таймер не переключает профиль на дебрифинг принудительно; возврат до четырёх секунд ведёт на поле, после — к дебрифингу. Возврат синхронизирует анимацию флагов с прошедшим временем.

## Проверки

Результат 2026-11-05: прошли 28 unit-тестов (14 новых), пять браузерных сценариев и production-сборка. Проверены снимки горения и финального состояния поля на desktop/mobile.

Unit-тесты: `npm test`. В `postBlastFlags.test.ts` проверены классификация, неизменность данных, снимок, снятые флаги, chord-взрыв, границы 899/900, 2499/2500, 3999/4000 мс, повторный запуск, очистка и реальные автофлаги Рома в solo/squad.

Браузерные тесты: запустить `npm run dev`, затем `npm run test:browser`. При первой установке выполнить `npx playwright install chromium`. Адрес можно задать через `TEST_BASE_URL`.

`scripts/test-post-blast-flags.mjs` проверяет реальные экраны приложения: ручной правый клик, мобильные касания, отсутствие подсказки до подрыва, промежуточные CSS-состояния, повторный рендер, дебрифинг, счётчики, пять стилей биомов, профиль и следующую операцию. Дополнительные проверки реальных `RunManager`/`BoardView`/`HudView` покрывают гибель, выживание с бронёй, границу `RUN_LOST`, неизменность поля и очистку до 900 мс.

Снимки фаз и биомов сохраняются в игнорируемой папке `.vite/flag-browser/`. Проверка телефонов выполняется в Chromium с touch/viewport/DPR-эмуляцией, не на физических устройствах. Safari/WebKit и производительность на слабых телефонах отдельно не измерялись.
